## Required changes
1. **Eligibility violates the goal and mislabels drafts as finished** (rollup.py lines 60–73 and 92–94). The goal says sector roll-up is built only from finished banks; the completion protocol defines acceptance using current independent PASS, core gate, no unresolved blocking review and owner done. This code includes `needs-review` unconditionally and `done` without verifying current acceptance. Current SG has a CHANGES review but entered my fresh run; other submitted packages may also have open blockers. Default to the supervisor's verified, current accepted set with package/macro fingerprints; explicitly show excluded and reasons. If an early working view is wanted, place it in a separately and repeatedly labelled **provisional** output, never call submitted banks finished or put them into the accepted sector figures. No eligibility should be inferred from quiet boards.
2. **Mixed operating-income basis creates non-comparable totals and ratios** (lines 122–128 and 135–148). Access 9M-2026 operating income is 1,096.184m **after** 13.969m impairment; its FY2025 annual 1,462.579m is **before** impairment. Pre-impairment 9M total on Access components is 1,110.153m. The script sums the mixed values without normalization and computes cost/income using each bank's reported denominator while labeling one comparison. Normalize to a defined like-for-like basis with explicit source/impairment treatment, or omit noncomparable totals and ratios and flag bank/period exclusions. Confirm treatment for every bank rather than adding impairment mechanically twice.
3. **Missing output becomes numeric zero** (lines 86–89 and 162–165). With no base FY2030E profit available for any included bank, my fixture produced `ALL_INCLUDED,0.000` in rollup.csv. A downstream reader cannot distinguish missing from a genuine zero, and CSV lacks the markdown's `n/total` coverage. Emit blank/null on no observations, provide counts and the list or fingerprint of banks in each aggregate; where coverage is partial clearly label incomplete and never compare it as a complete same-bank total. Apply same protection to historical totals, ratio numerators/denominators and zero/negative equity; avoid treating falsey numerical zero as missing.
4. **Output can silently go stale** (lines 178–181). Committed output includes seven banks and older inputs; a fresh main-snapshot run already includes eight and changes a seven-bank base FY2030E sum by 122.400m. Record exact repo commit, accepted bank list, package and macro fingerprints and generation UTC in both outputs; provide a deterministic freshness check or regenerate on input changes. Do not imply the old 43% or forecasts are current without checking the data snapshot. Snapshot acceptance and output should be atomically tied to the same inputs.
5. **Period/basis comparability** (lines 99–107 and 149–156). September bank data are divided by October sector figures despite the same-month BoG September data (500.2bn assets, 362.2bn deposits); add the September source observations, use same-date denominators and clearly state basis. The per-bank ROE uses closing equity, while the displayed BoG sector ROE may use another convention; do not present them as directly comparable without independently validating its denominator. Shared macro paths alone do not prove all bank scenario designs or accounting labels are comparable.
