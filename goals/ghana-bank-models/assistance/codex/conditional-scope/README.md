# Conditional completion proposal (not an acceptance decision)
Prepared by codex. The standalone prototype in this directory passed 26 synthetic cases in the JavaScript execution environment. It has not been wired into the live supervisor.

## Existing defect
In scripts/room-state.mjs (blob 370a9dfd666377d8590e53052c616a0ae28dc9f9), the ordinary PASS regex matches PASS-with-limitation. In scripts/completion.mjs (blob 48c4f4b9f023763f28ee9f50861d130c2bbd294d), one bound ordinary PASS, no outstanding blockers, a passing core gate, and status done produce accepted. The core schema counts annual periods, not latest published interim coverage. The lead's review-resolutions/prudential-bank.md is not machine-consumed. Consequently a qualified verdict could contaminate accepted-only aggregates. No claim that this contamination has actually occurred.

## Proposed integration (lead approval required)
1. Add explicit CONDITIONAL-PASS, and recognize PASS-with-limitation as conditional, never ordinary. Require exact current package/macro, exact decision-text SHA256, and exact scope label in each review. Preserve previous blocking reviews until genuinely re-reviewed or resolved under existing protocol. Review identities are taken from registered filenames, not arbitrary reviewer fields.
2. Use a separately authorized, machine-readable conditional scope record bound to the exact package/macro and decision text. Validate it against the lead-authored decision and genuine approval event (a JSON approvedBy string alone is NOT proof of authorization). For Prudential, enforce five FY2021–25 actual IS+BS periods, no numerical 9M26 history, FY25 anchor, FY26 estimates, recapitalisation sensitivity, label. Derive coverage from parsed CSV, not author assertions. The conditions object in the prototype represents integration-verified conditions, not a self-attestation.
3. Dispatch any bank subject to conditional scope or missing required published period through fail-closed conditional classification BEFORE ordinary assessment. Unknown/malformed/stale approval must remain excluded. For Prudential the ordinary route stays blocked until actual interim is recovered, package rebuilt and independently re-reviewed. Do not treat not-applicable as permission to waive other banks' source requirements.
4. Require TWO distinct eligible current CONDITIONAL-PASS reviews, no outstanding blockers, and owner close. Exclude owner, worker, prior stewards and substantive evidence contributors per lead's independence policy. The original Support blocker needs its exact qualified re-review. Papa owns the package; Codex supplied historical source evidence; Helper's former-claim role should be adjudicated by the lead. Do not fabricate independence.
5. Emit acceptance=conditional-accepted separately from accepted. Roll-up and peer comparison ordinary aggregates continue to filter exactly acceptance===accepted. Add a clearly segregated conditional table with missing-period label, scope hash, review hashes and snapshot fingerprint; never add conditional estimates to accepted-only totals. Report counts ordinary/conditional/unresolved separately. Keep ordinary goalComplete unchanged; lead may define a distinct scoped-ready flag and explicit human sign-off. Do not imply all 23 are ordinary accepted.
6. If an actual interim becomes available, conditional scope lapses; rebuild and re-review under ordinary gate. If package/macro/decision bytes change, conditional review binding lapses immediately. OmniBSIC/UMB would need their own independently approved scope and gate policy; this Prudential proposal is not transferable to those banks.

## Test and limitations
Run node conditional-scope-proposal.mjs. 26 synthetic cases include distinct review IDs, scope binding, missing history, failed core gate, old blocker, recovered interim, unregistered owner/source contributors and ordinary-vs-conditional exclusion. Production integration still needs parser/CSV coverage extraction, authorization provenance, supervisor, manifest/roll-up/peer-comparison end-to-end tests on pinned LF checkout, and lead review. Do not publish an approval file from this proposal. No bank, claim, review, supervisor or shared-output file edited.
